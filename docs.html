Mousr documentation

Mousr controls the pointer from the keyboard on Sway. It provides grid selection, mouse movement, clicks, drags, and scrolling.

Mousr runs as a Rust daemon. It uses Wayland protocols for outputs, overlays, keyboard capture, and pointer events. It uses Sway IPC for the focused output, cursor warps across outputs, and pointer actions when the virtual pointer protocol is unavailable.

Mousr currently supports Sway on Wayland only.

Requirements#

  • A Wayland session running Sway.
  • The Wayland client and libxkbcommon runtime libraries. Distribution packages install them.
  • For focus preservation, compositor support for zwp_input_method_manager_v2.
  • For the refinement lens, compositor support for screencopy.

Installation#

Packages are available for Ubuntu, Debian, Fedora, and Arch Linux. Prebuilt amd64 and arm64 archives and cargo install mousr are also available.

See the installation commands.

Quick start#

Add these lines to the Sway configuration:

~/.config/sway/config
exec mousr daemon
bindsym Mod1+space exec mousr grid
bindsym Mod1+Shift+space exec mousr mouse

Run swaymsg reload. Press Alt+Space to open the grid, type a label such as fk, and press s to left-click the cell.

To change settings, copy the example configuration to ~/.config/mousr/config.toml and run mousr reload.

Grid mode#

mousr grid covers the focused output with a grid of labelled cells and captures the keyboard.

  1. Type a label. Labels are fixed-width base-26 strings: a to z, then aa to zz. Cells that no longer match are dimmed. grid.unmatched controls this.
  2. Refine. A complete label selects the cell. Return subdivides it. BackSpace erases a character or returns one level.
  3. Act. Press an action key. Mousr moves the pointer to the cell centre and performs the action.

How cells are sized

The first level is derived from the output size and grid.root_min_tile_width × grid.root_min_tile_height The default is 96 × 54. Each refinement halves both targets until min_tile_width and min_tile_height are reached, then coarsens the level if needed to fit label capacity and max_cells.

With grid.refinement_zoom above 1.0, Mousr captures a fresh output image on each descent and draws the selected rectangle magnified inside a lens. The area outside the lens is dimmed. Minimum tile sizes then apply to the magnified display space. If screencopy is unavailable, refinement continues without the lens.

ui.lens_animation_ms sets the duration of the transition between levels. Keyboard input ends the transition.

Mouse mode#

mousr mouse, or g from a grid selection, starts continuous keyboard pointer control.

  • Movement. Hold h j k l. Speed starts at motion.initial_speed and ramps toward motion.max_speed along motion.curve. Fractional motion is preserved, so movement below one logical pixel per update is possible.
  • Buttons. s d f mirror key state for left, middle, and right. Hold one while moving to drag. Pressing s twice performs two left clicks; c sends an explicit double-click.
  • Button lock. Press v, then a button key, to hold that button without a chord. Press v again to release it.
  • Exit. Escape releases all held buttons and exits.

Scrolling#

u e y o scroll up, down, left, and right in grid and mouse mode. 15 units equal one wheel notch.

For your own bindings, mousr scroll up|down|left|right [--step AMOUNT] scrolls once. By default it targets the surface under the pointer. With scroll.target = "focused-window", it moves the cursor to the centre of the focused window's content first and leaves it there.

The virtual-pointer path sends the continuous amount with a discrete notch count rounded to the nearest whole notch, with a minimum of one. The Sway IPC fallback emits whole notches only.

Multiple outputs#

By default the grid covers the output containing Sway's focused workspace. Use --scope all to span every output with unique labels, or --output NAME to target one. Relative mouse motion uses the compositor's global logical coordinate space, so it crosses outputs according to your Sway or wlr-randr layout.

If a display or keyboard disappears during suspend/resume, the active mode is cancelled and held buttons are released. The keyboard is rebound when the seat returns.

Architecture#

Commands such as mousr grid connect to the daemon over a local IPC socket and exit. The daemon holds the session state and uses two adapters.

  • App (src/app.rs) owns commands, sessions, rendering, capture policy, animation, and motion.
  • DisplayBackend (src/backend.rs) supplies output geometry, focus, presentation, asynchronous capture, timers, and pointer events. The Wayland adapter implements it.
  • CompositorControl (src/compositor.rs) isolates compositor commands; src/sway.rs implements it.

The renderer produces packed, premultiplied BGRA frames. Default sessions take keyboard focus through layer-shell; the opt-in focus-preserving path uses a session-scoped input-method v2 grab. An adapter that cannot apply the focus policy must fail and must not take focus.

Logging#

Stderr uses compact DBG, INF, WRN, ERR, and PNC prefixes with UTC timestamps. Logging options apply to the current process, so start the daemon itself with debug logging to see daemon diagnostics:

shell
mousr --log-level debug daemon
mousr --log-level debug --log-file ~/.local/state/mousr/logs/debug.json daemon

--log-file also writes JSON-lines diagnostics to the given file.

Building from source#

Building requires a stable Rust toolchain and the libxkbcommon development files.

shell
git clone https://github.com/toxdes/mousr
cd mousr
cargo build --release
cargo install --path . --bin mousr

Debug builds identify as mousr-dev and use a separate IPC socket, so a development daemon can run alongside an installed release. Run ./target/debug/mousr cancel before restarting it.

cargo test --no-default-features tests the shared runtime without the Wayland and Sway adapters. See CONTRIBUTING.md for testing under Sway.
